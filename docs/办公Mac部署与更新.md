# 办公 Mac 部署与更新 · 后来居上组管理后台 V0.3.2

这份交接用于另一台**办公 Mac**。开发 Mac 负责开发与发布；办公 Mac 是唯一的正式服务和正式业务数据主机；Windows 电脑只用浏览器访问办公 Mac。当前仓库是[私有仓库](https://github.com/zengyies-ux/houlai-jushang-group-admin)。v0.3.2 只能在完成构建检查、正式 Release 发布后从 [v0.3.2 Release](https://github.com/zengyies-ux/houlai-jushang-group-admin/releases/tag/v0.3.2) 下载，不能使用源码 ZIP 冒充成品。该直达地址在正式发布前可能尚不可访问；部署前须先核实页面标为正式发布，成品附件和校验清单确实可下载。

## 第一次部署：照着做

1. 在办公 Mac 的「 → 关于本机」确认芯片是 Apple M 系列；也可在终端运行 `uname -m`，结果须为 `arm64`。当前 Mac 成品只支持 macOS arm64。若是 Intel Mac（`x86_64`），先取得并验证适配成品，不要试用 Apple 芯片包。检查是否已经有旧数据或正在运行的工作台；若有，先走下文“更新”或“迁移”，不能当空白新装。
2. 在**办公 Mac 自己的浏览器**登录有权限访问仓库的 GitHub 账号，打开上方 v0.3.2 Release 链接，确认它是正式发布版本。下载文件名以 `macos-arm64.zip` 结尾的**附件**及同一 Release 的 `SHA256SUMS.txt`。私有仓库凭据留在办公 Mac，不要复制开发机凭据，也不要把密码、令牌或验证码发给 Codex。GitHub 自动生成的 Source code ZIP 不是运行包。
3. 在 Mac 终端输入 `shasum -a 256`，把 ZIP 从 Finder 拖入终端并回车。将输出与 `SHA256SUMS.txt` 中该 ZIP 的一行逐字比对；不一致就重新下载，不能继续安装。解压 ZIP。推荐由办公 Mac 的 Codex 把**解压后的包内文件**放到 `~/Applications/后来居上工作台/releases/0.3.2/`，让 `~/Applications/后来居上工作台/current` 指向该目录，并在同级记下版本与实际路径。`current/启动.command` 和 `current/停止.command` 是固定入口，日后更新只切换 `current`。
4. 正式数据默认位于 `~/Library/Application Support/AIShortDramaWorkbench/data/`，与程序目录、Git 仓库及 iCloud 同步文件夹分开。首次确实没有数据才让程序创建空工作台，不导入演示任务。若该目录已有文件，先确认来源、当前进程和备份；不得用开发 Mac 的库覆盖。若确有业务数据要从开发 Mac 单次迁移，应先从源机做一致性备份，在办公 Mac 本机恢复并核对后，停止源机继续录入。两台机器的业务数据不会自动合并。
5. 双击 `current/启动.command`，让启动终端保持打开。浏览器应打开 `http://127.0.0.1:4173`；没有自动打开时手动访问。在「设置 → 技术信息与数据位置」确认 v0.3.2、`darwin/arm64` 和实际数据目录。双击 `current/停止.command`，重新启动后再次核对版本与目录。新空库不必为了验收而写入演示任务；若已有正式数据，核对既有成员、任务、历史、头像和背景，不为测试添加或删除业务记录。下一步保存局域网设置可验证写入及重启保留。
6. 在**办公 Mac 本机**「设置 → 局域网访问」输入至少 8 位访问口令、勾选允许访问并保存，停止和重启服务。设置页会给出办公 Mac 的局域网地址。Windows 电脑连接同一可信私有网络，在浏览器打开该地址并输入口令；例如地址可能是 `http://192.168.1.10:4173`，应以实际设置页为准。Windows 自己的 `127.0.0.1` 不是办公 Mac。口令、局域网开关和数据恢复只在办公 Mac 本机设置。
7. 在办公 Mac 本机「设置 → 备份与恢复」点「立即备份」，确认列表出现快照，点「下载」保存另一份。可额外保存在受控的外部备份介质。记录成品版本、程序目录、实际数据目录、备份存放位置和 Windows 实测地址，但**不要**把口令写进交接文件。

现有启动脚本在前台终端运行。关闭该终端或重启 Mac 后，需要再次双击启动；本版不提供自动登录启动或后台自动更新。办公 Mac 应保持开机、联网且不休眠。防火墙询问时只对可信私有网络允许本应用；建议在路由器保留固定局域网地址。局域网连接是 HTTP，口令和业务数据传输未加密，不能使用不可信 Wi-Fi，不要开放公网端口、关闭 macOS 系统保护或共享数据库文件。软件核心功能运行时无需连接 GitHub，只有下载安装才需要。

## 正式数据与备份

默认数据目录：`~/Library/Application Support/AIShortDramaWorkbench/data/`。数据库为其中的 `workbench.db`，备份位于 `backups/`；成员头像、背景和任务历史在数据库中。程序包不包含业务数据库；替换程序目录不会迁移或删除默认数据。GitHub 不替办公 Mac 备份正式任务；开发机应继续用隔离数据，想看正式数据可访问办公 Mac 网页。不要用 GitHub 或 iCloud 在两台 Mac 间双向同步正式库。

页面「立即备份」会生成 SQLite 一致性快照。服务运行时还会按需生成日备份，默认只保留最近 7 份日备份；关键更新前应另行下载并保存快照。**不要**从运行中的数据库只复制 `workbench.db` 而漏掉 WAL。恢复时先让所有设备停止编辑；在办公 Mac 本机把兼容的备份放进 `backups/`，再从「设置 → 备份与恢复」恢复。恢复会先保存当前库，之后所有页面要刷新。恢复旧快照会失去快照之后的修改，必须先保存当前状态并确认时间点。

正常部署不需要自定义 `DATA_DIR`。若实际使用了它，办公 Mac 执行者应把真实路径记录在本机部署记录中，并确保启动、停止、备份及每次更新都传同一个值；双击默认脚本时不会自动继承另一终端的临时环境变量。

## 以后更新正式稳定版

用户可把下文提示词交给办公 Mac 上的 Codex，说“更新到最新正式稳定版”。Codex 应选已正式发布、与芯片架构匹配且成品检查通过的版本，不追踪开发分支、每个提交、草稿或预发布版本。本版没有常驻自动更新服务；更新会短暂停用。

固定顺序：

1. 在旧版「设置 → 技术信息与数据位置」查看**当前版本、实际数据目录**，核对 `current` 指向及是否使用自定义 `DATA_DIR`。检查备份和目标版本的数据库兼容说明。
2. 从正式稳定 Release 下载新成品 ZIP 和同版 `SHA256SUMS.txt`，核对 SHA-256，把新程序放在新的 `releases/<版本>/`。先检查启动、停止脚本和包内文件，不碰正式数据库。
3. 通知所有正在用办公 Mac 或 Windows 网页的人员暂停编辑；在旧服务仍运行时点击「立即备份」并下载到程序和数据目录以外。**从备份开始到旧服务停止，不允许其他页面继续写入**，否则备份会漏掉新修改。
4. 用旧版对应的 `停止.command` 停止服务，确认 4173 不再由旧实例监听。保留旧版程序和更新前备份。让 `current` 指向新版本，只启动**一个**新实例；不能同时让新旧实例写正式库或执行迁移。
5. 检查本机页面版本、实际数据目录、小组、成员、任务、事件、头像、背景、访问口令和局域网设置；再从 Windows 浏览器核对连接和保存。结果无误后恢复日常编辑，并更新本机部署记录。

若新版启动失败，先保持停止状态、保存错误和当前数据库状态。**仅在确认数据库结构仍兼容时**，才可切回旧程序。发生结构迁移时，旧程序可能无法打开新库，不能强行启动。若必须恢复更新前备份，先另存当前状态，并明确备份之后的修改会丢失；不可静默回滚真实业务数据。

## 常见问题与成功检查

| 情况 | 应检查什么 |
| --- | --- |
| Mac 是 Intel 芯片 | 当前 arm64 包不适用；取得 Intel 适配构建并验证后再部署。 |
| 双击后没打开网页 | 看启动终端是否仍在、是否报 4173 端口占用；手动访问 `http://127.0.0.1:4173`。不要删除数据来“修复”。 |
| Windows 连不上 | 在办公 Mac 本机核对服务、口令、局域网开关和重启；使用设置页所列地址，检查同网、防火墙和休眠状态。 |
| 更新后似乎没数据 | 先核对 Mac 登录用户、页面显示的实际数据目录及 `DATA_DIR`；暂停录入，查旧版数据与备份，不覆盖疑似正式库。 |
| GitHub 附件下载不了 | 在办公 Mac 的浏览器用有仓库权限的账号登录；确认版本是正式 Release，下载的是附件而非源码 ZIP。 |
| 校验值不一致 | 停止安装，重新下载 ZIP 和同一 Release 的校验清单。 |

首次部署算完成，须至少看到：办公 Mac 本机显示正确版本及数据目录；停止再启动后数据仍在；一致性备份可在列表和下载位置找到；设置页显示局域网地址；Windows 用该地址成功打开并保存；实际芯片、系统、防火墙和首次打开行为已记录。开发 Mac 上的构建与冒烟检查不能代替这些目标机验收。
